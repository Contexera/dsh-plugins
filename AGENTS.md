# AGENTS.md

`dsh-plugins` is a pnpm monorepo of the published `@wowyuarm/dsh-*` plugins for
[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness). Each package
ships to npm independently; the repo only unifies install, tooling, and release.
It adds no cross-package coupling — the packages do not depend on each other.

## Authority order

1. **Current behavior:** each package's `src/` and `tests/`.
2. **Per-package guidance:** the package's own `AGENTS.md` (if present) and `README.md`. These own everything specific to that package — its architecture guardrails, boundary rules, and contract.
3. **This file:** monorepo-level layout, commands, and conventions only.
4. **Harness contract:** the applicable `deepseek-harness/docs/` pages and the published `@deepseek-ai/dsh-*` package declarations.

When this file and a package's own `AGENTS.md` disagree on a package-local rule, the package wins. Work inside one package at a time.

## Repository layout

```
package.json          Private workspace root: shared scripts + changesets only
pnpm-workspace.yaml   packages/*
tsconfig.base.json    Shared compilerOptions; every package tsconfig extends it
.changeset/           Independent per-package versioning
.github/workflows/    One CI gate: pnpm -r typecheck / test / build on Linux + Windows
packages/
  channel-gateway/      @wowyuarm/dsh-channel-gateway
  context-continuity/   @wowyuarm/dsh-context-continuity (see its AGENTS.md)
```

Each package is self-contained: its own `package.json`, `tsconfig.json`
(extends the root base), `tsconfig.build.json`, `vitest.config.ts`,
`scripts/check-boundaries.mjs`, `src/`, `tests/`, `docs/`, and README. The
boundary guard's allowed-peers list is package-specific and lives with the
package — do not merge these scripts.

## Commands

```sh
pnpm install                 # pnpm workspaces, node >=22
pnpm -r typecheck            # strict TypeScript, no emit, every package
pnpm -r test                 # each package's boundary check + unit tests
pnpm -r build                # emit each package's lib/
pnpm --filter @wowyuarm/dsh-context-continuity test   # one package only
```

Run the narrowest check for the surface you touched: a single package via
`--filter`, the whole repo via `-r` only for a repo-wide change. CI owns the
exhaustive Linux + Windows matrix.

## Conventions

- **pnpm only.** The workspace is driven by `pnpm-workspace.yaml`; there is no root or per-package `package-lock.json`. Use `pnpm`, not `npm`, in the repo.
- **Independent versioning via changesets.** Packages carry their own version and release on their own cadence (`fixed: []`, `linked: []`). Never lockstep them. Record intended bumps with `pnpm changeset`, apply with `pnpm version-packages`, publish with `pnpm release`.
- **Depend on published `@deepseek-ai/dsh-*` packages** (prebuilt `lib/`), declared as `peerDependencies` and pinned in `devDependencies`. Do not add path mappings to a local Harness checkout: fast, checkout-free tests are why these packages exist standalone.
- **Package boundaries are enforced.** `src/` may import only its own relative modules, `node:` builtins, and the peers the package declares; `check:boundaries` (run first by `test`) fails on any leak. A package must never import another `@wowyuarm/*` package's source.
- **ESM, strict TypeScript.** `"type": "module"`, `.ts` in local relative imports, `exactOptionalPropertyTypes`-clean. `lib/` is generated by `build`; never hand-edit it.
- **Comments state non-obvious constraints and reasons, never restate code.** Update a package's `README.md` and tests together when a change alters its public contract.

## Adding a package

1. Create `packages/<name>/` with its own `package.json` (`@wowyuarm/dsh-<name>`, independent version), a `tsconfig.json` that `"extends": "../../tsconfig.base.json"`, `tsconfig.build.json`, `vitest.config.ts`, and a `scripts/check-boundaries.mjs` listing its declared peers.
2. Give it `build` / `test` / `typecheck` scripts matching the existing packages so `pnpm -r` picks it up.
3. `pnpm install` to link it, then `pnpm --filter @wowyuarm/dsh-<name> test`.
